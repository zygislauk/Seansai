# Data Model: Findable in Search Engines

**Feature**: [spec.md](./spec.md)

No database changes. The new structures are computed from the existing data, and the snapshot is files in
a deployment.

## API addition: `MovieDetailResponse.showingAt`

Added to `GET /api/v1/movies/:movieId` ([feature 001 contract](../001-cinema-showtimes/contracts/public-api.md)).
Additive, and has to be live before the snapshot code ships ([plan](./plan.md#rollout-order)).

```ts
showingAt: Array<{ id: string; name: string; cityId: string; cityName: string }>;
```

- Cinemas with a screening of this movie that hasn't started, within the requested `city` (`all` means every
  shown cinema).
- Ordered by city name, then cinema name. Empty when there are none.
- `cityName` follows the route's new `lang` option, default `lt`, as on the screenings route.
- One query, with no N+1 (Constitution VI).

With `screeningDates[0]`, this gives the movie summary (FR-005): when and where the movie is next showing.

## API addition: `CitiesResponse.cities[].hasMovies`

Added to `GET /api/v1/cities`. Additive, and has to be live before the code that reads it ships
([plan](./plan.md#rollout-order)).

```ts
hasMovies: boolean;
```

- True when any shown cinema in the city has a screening that hasn't started.
- Decides which city links the general list shows, and which city pages are in the site map.
- One query that stops at the first screening it finds for each cinema, as every page requests `/cities`.

## PageHead

What a page says about itself. Built by one pure function, `pageHead(page, lang)`, used both by the snapshot
(written into `<head>`) and by the running app (kept up to date as people navigate).

| Field | Rule |
|-------|------|
| `title` | Unique among site map pages (SC-002). Movie: title, plus year if known, plus "seansai". City: "Kino seansai Vilniuje". |
| `description` | Up to about 155 characters, in the page's language, from known facts only. Movie: where it's showing, next date, and genres on Lithuanian pages, as the sources only state them in Lithuanian. When space runs out, genres go before when and where. |
| `canonical` | Full address of the preferred page (FR-012), from `SITE_URL`. |
| `alternates` | `lt`, `en` and `x-default` (Lithuanian): the same set on both versions. |
| `image` | The poster, or the default preview image. |
| `imageAlt` | The movie's title, or the site's name. |
| `type` | `video.movie` for movies, `website` otherwise. |
| `robots` | `noindex` for the not-found page. Nothing elsewhere. |

### Preferred address

| Requested | Preferred |
|-----------|-----------|
| `/{lang}/` | Itself |
| `/{lang}/?city=vilnius` | `/{lang}/city/vilnius` |
| `/{lang}/?city=all` | `/{lang}/` |
| `/{lang}/city/{cityId}` | Itself |
| `/{lang}/movie/{movieId}` with any of `date`, `city`, `cinema`, `format`, `audio` | `/{lang}/movie/{movieId}` |

The snapshot only ever has the plain addresses. The app applies this table when it starts, for addresses with
options.

## Snapshot

Generated by each build and contained in that deployment:

```text
dist/
├── {lang}/index.html                 # General list
├── {lang}/city/{cityId}/index.html   # One per city with supported cinemas
├── {lang}/movie/{movieId}/index.html # One per current movie
├── 404.html                          # App shell, noindex
├── sitemap.xml
└── robots.txt
```

Each HTML file contains:

- `<html lang>`, the PageHead tags and the stylesheet link.
- `<meta name="snapshot-date" content="YYYY-MM-DD">`, in `<head>` so `boot-gate.js` can read it before the
  body is parsed.
- Rendered markup inside `#root`.
- `<script type="application/json" id="initial-data">`: the dehydrated query cache for the page.

### Lifecycle

| Event | Result |
|-------|--------|
| Refresh finishes with at least one source updated | Hook is called and a new snapshot replaces the old one when its build succeeds |
| Movie disappears from the data | It has no page in the next snapshot, so it gets 404 and leaves the site map (SC-004) |
| New movie appears | Gets a page and a site map entry in that snapshot |
| API fails or the general list is empty during a build | Build fails and the previous snapshot stays live |
| Refresh doesn't run (the Mac is off) | The snapshot stays as it is, with its "updated at" time |

## Site map entry

| Field | Rule |
|-------|------|
| `loc` | Full percent-encoded address of a plain page, for every current movie, general list and city list with current movies, in both languages |
| `lastmod` | The snapshot's data date |

Priority and change-frequency values are left out because Google ignores them.

## Settings on the device

| Key | Where | Value | Change |
|-----|-------|-------|--------|
| `seansai.city` | localStorage | City id or `all` | Now means "they've answered". Absent means first visit. |
| `seansai.lang` | localStorage | `lt`, `en` | Unchanged |
| `seansai_lang` | Cookie, 1 year, `SameSite=Lax`, `Secure` on HTTPS | `lt`, `en` | New. Written with `seansai.lang`, read only by the `/` redirect. |

## Configuration

| Setting | Where | Purpose |
|---------|-------|---------|
| `SITE_URL` | Constant in `apps/web/src/lib/site.ts` | The one public address (FR-022). A move to `seansai.lt` changes this line. |
| `VERCEL_DEPLOY_HOOK_URL` | Secret: `refresh.env` and Vercel Production | Optional. Unset means no hook call. Never logged. |
